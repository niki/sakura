仕様リファレンス — sakura_core

単一exe化 ファイル依存関係リファレンス

sakura.exe が「起動・編集・保存・検索置換・シンタックスハイライト」という中核機能を、同梱ファイルなしの単体配布でも問題なく提供できることを確認した記録。どのファイルが本当に必須で、どのファイルが「あれば使うが無くても壊れない」任意の拡張なのかを一覧化する。新機能で外部ファイルへの依存を追加する際は、このページの表に追記し、フォールバック(または明示的なopt-in)を必ず実装すること。

初版 2026-09-01 検証 2026-08-27（空フォルダにexe単体を配置しGUI自動操作で動作確認）

01起動に必須なファイル

結論から言うと、sakura.exe 本体以外に必須のファイルは無い。

項目状態備考
sakura.exe 必須 これ単体で編集・保存・検索置換・シンタックスハイライトが動作する。
sakura.ini 自動生成 存在しなければ既定値で起動し、初回実行時にプロファイルフォルダ配下へ自動作成される。

02任意の外部ファイル（無くても機能低下のみ、クラッシュしない）

以下はいずれも「存在すれば使う／存在しなければ静かにフォールバックまたは無効化」という設計になっている。

ファイル機能無い場合の挙動関連コード
bregonig.dll / bregonig64.dll 正規表現エンジン（鬼雲/Oniguruma系） 静的リンク済みのPCRE2へ自動フォールバック。置換ダイアログのステータス行に fallback: bregonig.dll not found と明示表示される。 extmodule/CBregexpDll2.cpp
言語リソースDLL（多言語UI用） メニュー等のUI文字列の多言語化 読み込めなければexe自身のインスタンスハンドル（内蔵の既定言語）を使う。 CSelectLang.cpp
Migemo辞書＋DLL ローマ字によるあいまい（ひらがな）検索 Migemo機能自体が使えなくなるだけで、他の検索機能・起動には影響しない。 extmodule/CMigemo.cpp
外部Winヘルプ/HTMLヘルプ（.hlp/.chm） オフラインヘルプ表示 既定は空文字＝そもそも参照されない。共通設定またはタイプ別設定でユーザーが明示的にパスを指定した場合のみ使う完全opt-in。 env/CHelpManager.cpp
sakura.keywordset.csv 強調キーワードセットの外部CSV管理・再読込 無ければCType.cppに組み込まれた既定キーワードセットをそのまま使う。主要言語のシンタックスハイライトは支障なし。 CKeyWordSetMgr.cpp/.h
プラグインDLL（plugins/配下） マクロ／プラグインによる拡張 該当プラグインが一覧に出ない・実行できないだけで、他機能には影響しない。 extmodule/CDllHandler.cpp, prop/CPropComPlugin.cpp
補足 — キー割り当てプリセット

かつては keybind_presets/*.key という外部ファイルだったが、2026-08-13の変更で sakura_rc.rc に RCDATA として埋め込み済み。現在は外部 .key ファイル無しでプリセット切替が完結する（prop/CPropComKeybindList.cpp）。Publish/keybind_presets*.zip は過去の配布形態の名残。

03Publishに同梱されているが、現行コードから未参照のもの

Publish/lua53.dll_ ・ Publish/lua53_64.dll_ は、sakura_core 全体を lua でgrepしても実コードのヒットが無い（ヒットは全て Evaluate 等への誤爆）。現行の sakura_core にLua連携機能が存在しないため、単一exe化の観点では実害はないが、古いプラグインサンプル（plugins_20170629.zip）向けの残骸である可能性が高い。配布物整理の候補として残しておく。

04検証履歴

2026-08-27、Release64\sakura.exe だけを新規の空フォルダにコピーし、専用の使い捨てプロファイル（-PROF=）で起動してGUI自動操作（PrintWindowによるスクリーンショット＋SendKeys／EnumChildWindows+SendMessage(BM_CLICK)）で以下を確認済み。

  • クラッシュなく起動し、メニュー・ツールバー・ルーラー・ステータスバーまで正しく描画される。
  • sakura.ini がプロファイルフォルダ配下に自動生成される。
  • 日本語テキストの入力・保存が正しく行える。
  • .cppとして保存した瞬間、組み込みキーワードテーブルだけでC/C++のシンタックスハイライトが正しく効く。
  • 置換ダイアログの正規表現エンジン表示が PCRE2 ... (fallback: bregonig.dll not found) になり、フォールバックが実際に使われていることが画面上で確認できる。
  • すべて置換を実行し、正しく置換・再描画される。
  • プロセスは安定動作し、終了後にゴミプロセスが残らない。

05新機能を追加するときのルール

外部ファイル（DLL・設定ファイル・データファイル等）に依存する機能を新規に追加する場合は、次のいずれかを満たすこと。

  • フォールバック方式 — ファイルが無ければ組み込みの代替実装／既定動作に自動的に切り替える（例: bregonig→PCRE2）。
  • opt-in方式 — 既定では参照せず、ユーザーが設定で明示的にパスを指定したときだけ使う（例: 外部ヘルプ）。
  • 機能単位の無効化 — その機能だけが使えなくなるにとどめ、起動や他機能に影響させない（例: Migemo, プラグイン）。

いずれの方式であっても、対応後は本ページ（02節の表）に追記すること。
