PPA・WSH代替マクロエンジン

サクラエディタのマクロは元々、外部DLL(PPA.DLL)またはOS登録済みの外部COMコンポーネント(WSHのJScript/VBScriptエンジン)に依存していた。どちらも「配布・保守が止まっている」「将来のWindowsで無くなる可能性がある」という共通の弱点を持つため、静的リンク済みのQuickJS(JavaScript)エンジンを土台にした代替を追加した。3本のchangelog(changelog/NKMM_FIX_QUICKJS_MACRO.md他)の要約と「できないこと」の一覧をまとめる。

01背景と全体像

PPA.DLL（Poor-Pascal for Application、ソース非公開の外部Pascalインタプリタ）は、本フォークでは2017年からNKMM_USE_PPAが無効化されており、事実上使えない状態だった。WSH(Windows Script Host)はOS登録済みの外部COMコンポーネント(JScript.dll/VBScript.dll)への依存で、無効化されている環境や、セキュリティ上の理由・将来のWindowsで廃止された環境では.vbsマクロが動かなくなる。

どちらも「マクロ関数本体(CEditorIfObj等のMacroFuncInfoテーブル)」自体には依存しておらず、依存していたのは「スクリプトエンジンへの接続部分」だけだった。そこでこの接続部分を、静的リンクしたquickjs-ng(MIT License、libs/quickjs/にvendor)向けに1つ作り、Pascal風・VBScript風のソースはこれ向けにJavaScriptへ変換してから流し込む、という設計にした。

セキュリティ上の副次効果

QuickJSに公開しているのはCEditorIfObj等が明示的に登録した関数だけで、WSHのActiveXObject("Scripting.FileSystemObject")のような無制限アクセスの穴が無い。結果としてWSH版より狭いサンドボックスになっている。

02拡張子と優先順位

拡張子担当ルール
.qjs 新規 QuickJS直接実行 新設の専用拡張子。他エンジンと衝突しない固定判定。
.pas 新規 Pascal→JSトランスパイル 新設の専用拡張子。旧PPAの.ppaとは別物（互換変換ではない）。
.vbs 共存 WSH優先、無ければVBS→JSへフォールバック 登録順(CWSHMacroManager::declare()→CVbsMacroMgr::declare())により、WSHのVBScriptエンジンがレジストリに登録されている環境では従来通りWSHが処理し、無い環境でのみ自動的にトランスパイラ側へフォールバックする。利用者は環境の違いを意識せず同じ.vbsを書けるが、フォールバック時は後述の対応サブセットの制約を受ける。

WSHが無い環境の動作を確認するためのNKMM_USE_WSHフラグ（既定で有効）もある。無効化するとCWSHMacroManager自体がコンパイルから除外され、レジストリの実際の状態に関わらず確実に「WSHが無い」状態を再現できる。

03QuickJSマクロ（.qjs）

拡張子.qjsのマクロファイルを、素のJavaScriptとしてそのまま実行する。Editor系関数はEditor.InsText()のような修飾付き呼び出しと、InsText()のような修飾無し呼び出しの両方に対応。

できないこと・制限

  • 引数の型変換はVT_I4/VT_R8/VT_BSTR/VT_BOOL/VT_EMPTYのみ対応。BigInt・オブジェクト・配列はそのまま渡せない（コマンド呼び出し経路では文字列化される）。
  • COutlineIfObj/CSmartIndentIfObj/CComplementIfObj（アウトライン解析・スマートインデント・補完のプラグイン拡張ポイント）は未接続。プラグインからこれらを使うマクロは書けない。
  • Promise/async/awaitは実行環境自体は有効だが、マクロ実行がジョブキューをポーリングしない同期モデルのため実質動作しない（.then()やawaitの継続が呼ばれるタイミングが無い）。
  • Proxy・WeakRef・performance.now()は実行ファイルサイズ削減のため無効化済み（Date.now()は使用可）。
  • 新規ファイルはUTF-8 BOM付きで保存する必要がある（BOM無しはCP932として誤読される既存仕様）。

04Pascal風マクロ（.pas）

PPA.DLLの代わりに、独自の軽量トランスパイラ(CPasToJsTranspiler)でPascal風ソースをJavaScriptへ変換し、QuickJSエンジンで実行する。S_接頭辞（例: S_InsText）でサクラのEditor API、無印の呼び出しはPPA標準ライブラリ相当のランタイム関数として扱う。

できないこと・制限

  • 非対応 (* ... *)形式のブロックコメント（{ ... }と//のみ対応）。
  • 非対応 文字コードリテラル（#13等）、単項+、case文、function宣言（procedureのみ）。トランスパイル時にエラーとして検出される（無限ループはしない）。
  • 形だけ 型注釈（: Integer等）は構文としてスキップされるだけで、型チェックは一切行わない。
  • 注意 識別子の大文字小文字を正規化しない。元のPPA環境では動いていた表記ゆれのあるコード（例: MDaysとMdaysの混在）はJS変換後にReferenceErrorになる。
  • 意味の違い Lengthは「バイト数」ではなくUTF-16コード単位数を返す。
  • .pasファイルはUTF-8(BOM付き)で保存必須（BOM無しはShift-JISとして誤読され文字化けする）。

05VBScript風マクロ（.vbsフォールバック）

WSHが使えない環境でのみ、CVbsToJsTranspilerがVBScript風ソースをJavaScriptへ変換してQuickJSで実行する。MsgBox/InputBox等、サクラ本来の同名関数と引数の意味が異なる組み込み関数は、Pascal版と同じS_接頭辞規約でサクラ側を呼び分ける。

できないこと・制限

  • 非対応 Class...End Class（クラス構文自体）。
  • 非対応 COM/ActiveXオブジェクト全般（CreateObject、Newによるオブジェクト生成、プロパティ/メソッドのドット記法アクセス）。ブラウザ/Node.js相当の実行環境が無いため意図的に対象外。
  • 非対応 行ラベル・エラー処理以外のGoTo。On Error Resume Next等は構文として無視されるだけで、実際のエラー握りつぶし動作は再現しない。
  • 制限あり 配列は1・2次元のみ（3次元以上はエラー）。ReDim Preserveは1次元のみ。配列名の判定が単一パスのフラットなスコープのため、宣言前の使用や、実行時に配列を返す関数の戻り値（例: Splitの結果）への添字アクセスが誤動作しうる。
  • 再現しない ByRef引数は実際の参照渡しにならない（JSの値渡しの制約）。
  • 簡略化 NothingとNullはどちらもJSのnullに畳み込まれ、区別されない。
  • 注意 大文字小文字を正規化しない（Pascal版と同じ制限）。

063エンジン共通の制限

  • プラグインの拡張ポイント（アウトライン解析・スマートインデント・補完）はQuickJS系のいずれのエンジンにも未接続。これらを使う既存のWSHマクロ・プラグインは、WSHが使える環境でしか動かない。
  • いずれのトランスパイラも識別子の大文字小文字を正規化しない。元言語（Pascal/VBScript）は大文字小文字を区別しないが、変換後のJavaScriptは区別するため、表記ゆれのある既存マクロ資産は移植時に修正が要る。
  • 関数の引数として渡せる型はスカラー値（整数・実数・文字列・真偽値・空）のみ。オブジェクトや配列を直接やり取りする既存マクロは書き換えが必要。

07未検証の項目

重要

3本のchangelogはいずれも「サンドボックス環境ではフルビルド(リンクまで)が既存の問題で通らない」ため、ファイル単位コンパイル確認・Node.js上のモック実行確認までしか行われておらず、sakura.exe実機上での動作確認の多くが未実施と明記されている。2026-08-27以降、macro配下に追加の検証コミットは無い。実機で機能を使う前に、少なくとも以下は確認したほうがよい。

  • .qjsマクロの実機実行、マクロ停止ダイアログでの中断、plugin.defにType: qjsを指定したプラグインの実機動作。
  • .pasマクロの実機実行（Editor.InsText()とInsText()の両呼び出し形式、構文エラー時のダイアログ表示）。
  • .vbsのWSHフォールバック — WSHが使える環境で既存挙動が変わらないこと、WSHを外した環境でCVbsMacroMgrへフォールバックすること。
  • 削減後の実際のsakura.exeファイルサイズ（QuickJS組み込みにより約2.2MB→約4.0MBに増加したとの記録があるが、その後の機能絞り込みでどこまで戻ったかは未実測）。
